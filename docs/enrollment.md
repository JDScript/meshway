# 控制面注册与持久化

当前控制面使用多网络SQLite、本地用户session/网络RBAC、实例bootstrap、网络内接入令牌与节点专属bearer，分别授权。注册建立HTTP身份；托管邻接/E2E另用[绑定公钥](/connections)和[数据面认证](/managed-dataplane)。

用户账户/邀请/网络角色/设备归属已接线，见[账户](/local-accounts)。CLI链接登录与tag身份接入的后续范围独立推进，OIDC后续；不能混同人类登录、实例权限、接入秘密与节点身份。

这套身份已扩展到通过集成验收的[地址与配置分发](/configuration)。注册基线和新增配置 / 路由闭环分别记录实际证据，见[开发路线](/development)。

## 凭据与权限

| 凭据 | 获取与保存 | 权限边界 |
| --- | --- | --- |
| 用户session | 邮箱密码登录返回不透明`mws_`，浏览器私有保存 | 当前membership/网络角色；本人设备批准与账户操作，不得跨网 |
| 实例bootstrap bearer | 首次启动创建私有`admin.token`，显式读取 | 初始化/恢复与兼容管理入口；不成为用户设备owner，不授给网络Owner |
| 注册bearer | 本网Owner/Admin创建，原值仅返回一次 | 原子绑定一个节点；不能读取管理清单 |
| 节点 bearer | Agent 在首次注册请求前生成随机凭据并持久保存；controller 保存摘要 | 代表该节点提交心跳；本轮增加读取自身公共配置及 ACK，仍不能调用管理 API |

HTTP 使用 `Authorization: Bearer …`。节点 ID 由服务端建立并从节点凭据解析，心跳和本轮配置 / ACK 请求没有调用方任选的节点 ID。节点名、版本、国家和分配地址都不能代替身份凭据或访问授权。

原始注册令牌仅在创建响应中交付；当前 API 没有重新读取它的接口。常规日志不得打印管理员令牌、注册令牌或节点凭据。

## 注册与恢复

App经[用户浏览器SSO](/device-login)批准本人设备，用短期S256 PKCE结果兑换；membership/ownership与node/IP/code消费同事务，生成统一节点。不增加App类别；原token/身份/地址/公钥/策略保留。

为避免“controller 已提交，但 Agent 丢失成功响应”造成身份丢失，采用可恢复注册方案：

1. Agent 先生成随机节点凭据，将待注册状态私有、原子地写入本地状态文件，成功后才发送请求。
2. 使用注册 bearer 提交节点凭据及名称、版本；controller 校验令牌期限和请求。
3. 在同一 SQLite 事务中消费令牌、创建节点并绑定凭据摘要；不同凭据并发消费同一令牌时，只能有一个成功的新身份。
   令牌所属网络同时决定节点归属与 IPAM；不能在注册请求中选择另一张网络。节点身份 / 凭据 controller 全局唯一、地址网络内唯一，跨网络复用凭据拒绝。
4. 成功返回服务端节点记录；Agent 原子更新本地状态，后续启动复用这一身份。
5. 响应丢失时保留原凭据。相同令牌、凭据及原注册元数据的重试返回同一个仍有效的节点，不创建第二条记录；不同凭据不能复用已消费令牌。
6. 若服务端已经接受注册，节点凭据心跳可返回节点记录，恢复尚未保存服务端 ID 的本地待注册状态。
7. 撤销记录阻止心跳，也阻止通过原注册请求恢复为有效节点。

“一次性”限制的是创建新身份的机会；同一身份的幂等恢复不重复消费或新增节点。期限限制首次消费，未消费的过期令牌返回 HTTP `401`；已绑定令牌即使经过原到期时间，相同原注册请求也可恢复仍有效的节点。不同凭据或元数据返回 `401`，已撤销节点返回 `403`；使用另一令牌提交已绑定的节点凭据返回 `409`。心跳恢复成功注册的身份，不意味着一个从未成功注册的凭据可以绕过注册令牌。

## 持久化与本地文件

controller 使用 `--data-dir` 指定目录，创建以下文件：

| 文件 | 用途 |
| --- | --- |
| `controller.sqlite3` | 节点、令牌期限与消费绑定、凭据摘要及撤销状态 |
| `admin.token` | 供管理员显式读取的原始管理员凭据 |
| `transport-material.key` | 托管材料加密密钥，与数据库一同私有备份 |
| `controller.lock` | 保证同一数据目录只由一个 controller 使用 |

首次启动创建状态，后续启动复用；`admin-token` 只显式读取既有令牌，不初始化状态。既有数据库与令牌只剩其一，或两者不匹配时拒绝启动，不会静默建立另一份管理员身份。

Agent 通过 `--state` 指定状态文件，默认 `.meshway/agent.json`；对应锁文件为 `.meshway/agent.json.lock`。状态保存 controller 地址、节点凭据、原注册名称 / 版本、注册令牌摘要及服务端节点 ID。原始注册令牌不写入状态文件。凭据在首次网络请求前持久化，文件使用私有临时文件、同步写盘和原子替换；损坏、权限不符、绑定不一致或被外部替换的状态被拒绝，不会被新身份覆盖。

文件发布前先打开父目录。`NotCommitted` 表示尚未发布，旧文件保留；`CommittedNotDurable` 表示新身份文件已可见，但发布后的目录同步失败，崩溃持久性未确认。后一种情况保留已发布的内存身份并返回失败，不能仅回滚内存或改建凭据。CLI 文件错误结束当前调用；后续重试复用已发布绑定，并在凭据使用前重新同步私有文件和父目录，成功后才继续网络操作。配置缓存采用相同[提交与持久性语义](/configuration#文件发布与持久性是两个阶段)。

当前私有存储要求 **Unix 文件权限**：新建目录为 `0700`，状态、令牌、数据库和锁文件为 `0600`，并校验当前用户所有权。Agent 状态文件的父目录也必须私有；默认 `.meshway` 在不存在时自动私有创建。自定义路径应使用自己的私有目录，不能直接放在组 / 其他用户可访问的目录中。非 Unix 平台尚未实现等价的私有存储。

`agent status --state …` 输出 controller 地址、名称、节点 ID 和 `pending` / `enrolled` 注册状态；本轮增加本地缓存的版本、摘要和双栈地址。它不输出凭据，不查询服务端最新回执，也不探测在线情况。复制身份状态文件会复制这一控制面身份，节点名相同则不代表同一身份。

这是**单controller的SQLite部署**。接入绑定、节点地址/身份/ownership与revision在同事务提交；当前schema直接初始化，不保留历史数据库升级或旧策略转换。Agent身份持久化与业务快照分别拥有生命周期，不能以存储初始化证明隧道已建立。

## 心跳、清单与撤销

- `registered_at` 是注册时间；`last_seen` 是 controller 最近接受注册或心跳的时间，两者为 RFC 3339 时间。
- `revoked_at` 为时间字符串或 `null`；撤销后保留清单记录。
- 概览的 `node_count` 统计所有持久化节点，**包括已撤销节点**，不能标成在线节点数。
- `agent run` 启动后立即心跳，再进行配置同步；成功后按 `--interval-seconds` 继续，默认 15 秒。可重试故障按 1、2、4…秒退避，最多 60 秒，成功后重置；HTTP `401` / `403` 和本地文件错误使进程退出，文件恢复后可另行重试。进程运行、心跳或配置 ACK 都不能证明 TUN、节点间传输或隧道已建立。
- 撤销使该节点控制面凭据被拒绝。普通心跳模式不建立隧道；托管运行层已实现撤回与 lease 到期终止旧代际，见[连接应用](/connection-runtime#应用与撤回)，不能只凭 HTTP 拒绝推断活动流已终止。

## Web 管理员边界

既有Next Web日常用用户账户登录，会话仅服务端私有cookie持有；每个受保护读取/管理Server Action重新检查身份，再经生成SDK请求，Controller也在根事务验证membership/role/过期。实例凭据只在setup/恢复兼容入口，不写HTML/Flight或日志，匿名action不能执行。

编辑器显式绑定渲染时network ID与CAS，选择cookie只是界面上下文，另一标签页不能改保存目标。图形/JSONC草稿与注释/错误保留，preview不推进base，手工国家入口已移除。仅明确过期/401清会话；暂时不可达保留会话并报错。

新`apps/console` pure SPA由独立工作流维护，已确认不透明`mws_`/LocalStorage/内存捕获/Authorization，无BFF；实例token仅内存。它不沿用Next cookie实现，仍由Controller逐请求鉴权。见[SPA合同](/spa-api-audit)。Next的HttpOnly/Secure配置见下节。

## 本地与远程部署

回环地址上的 HTTP 用于本地开发。**任何非本地部署都需要 TLS**，覆盖浏览器到 Web、Web 到 controller、Agent 到 controller 等经过网络的凭据传输。

当前选择将远程 TLS 终止交给部署层，例如独立反向代理；本切片不实现自定义 TLS 服务。应限制明文上游在本机或受保护的部署边界内，不能因为有 bearer 就允许明文跨不可信网络。控制通道 TLS 保护这些 HTTP 凭据，不等于实现 mesh 业务流量的 E2E。

### Web cookie 的 Secure 配置

`MESHWAY_WEB_COOKIE_SECURE` 由 Next.js 服务端读取：

| 配置值 | 行为 |
| --- | --- |
| `true` | 始终设置 `Secure`；远程 HTTPS 部署可显式使用此值 |
| `false` | 不设置 `Secure`；用于本地明文 HTTP 开发 |
| 未设置、空值或 `auto` | 优先按请求 `Origin` 是否为 HTTPS 判断；没有 `Origin` 时检查 `X-Forwarded-Proto` 的首个值 |
| 其他值 | 设置 `Secure`；非法 `Origin` 也按 `Secure` 处理 |

值会去除前后空白并转为小写。使用 `auto` 的 TLS 终止代理需要正确传递外部协议，并控制转发头来源；也可为远程 HTTPS 部署明确设置 `MESHWAY_WEB_COOKIE_SECURE=true`。该变量只设置 cookie 属性，不为 Web 或 controller 启用 TLS。
