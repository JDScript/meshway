# 运行方式与本机接口

**新 Agent 设计。** daemon／CLI 分离和两种网络模式已确认；本页的命令细节与状态组织为下一版提案。

## 两种网络模式

| | 系统 TUN | Userspace networking |
| --- | --- | --- |
| 应用接入 | 应用使用 OS socket，受管流量通过系统路由进入 TUN | 不创建 TUN，通过用户态网络栈及其应用接入接口使用 Mesh |
| TCP/IP 栈 | 本机应用通常使用 OS 内核 TCP/IP 栈 | 相应流量由用户态 TCP/IP 栈处理 |
| Meshway 逻辑 | daemon 内的准入、连接、加密与路径组件 | 复用相同的准入、连接、加密与路径组件 |
| 系统资源 | TUN、路由、DNS 接入，以及获准出口需要的转发／NAT 等 | 以用户态 socket／栈资源为主，不代表任意宿主应用自动被接管 |
| 失败表达 | 权限或安装失败如实报告，不能宣称系统流量已接管 | 接入接口、协议支持或栈资源不可用时如实报告 |

二者都使用系统提供的底层 socket 传输外层流量。内核模块、内核内加密或 eBPF 加速不由“系统 TUN 模式”隐含要求。

```text
系统应用／OS TCP-IP 栈 ⇄ TUN ─────────┐
                                    ├⇄ 共同 dataplane ⇄ 获准连接／transport ⇄ peer
用户态应用接入 ⇄ netstack ──────────┘
```

模式适配改变包的接入和交付方式，共同的数据面仍验证相同的节点身份、业务许可和完整路径。内核转发／NAT 与用户态出口适配分别报告能力，不能把一种模式下已实现的出口语义直接宣称为另一种模式已支持。

Userspace 不等于普通代理账户／订阅服务。具体应用接入方式尚待确认，例如本机 SOCKS5／HTTP 接入适配或应用内 socket 接口；若采用本机代理入口，它与 Meshway 内部的 transport provider 是不同职责。无 TUN 的纯中转也不等于已经提供了用户态端点网络栈。

模式是节点实际能力和执行的一部分，不能变成另一套服务器／终端节点类别。默认模式和云端字段尚待确定；不能因 TUN 安装失败静默切成 userspace 后仍报告原目标已 applied。同一安装中可以加载两种实现；同一设备一次只激活一个网络的边界保持。

## CLI

用户已明确日常入口为 `up`、`down`、`ping`、`status`，网络切换属于少量设备侧选择。以下是推荐语义，精确参数与输出合同后续定版。

| 命令 | 作用 |
| --- | --- |
| `meshway up` | 请求 daemon 上线；首次需要浏览器接入，已有身份则持钥认证并取得新实例／执行资格 |
| `meshway down` | 停止当前网络执行，释放／终止相关运行资格；daemon 继续提供本机 IPC，私有身份保留供再次 up |
| `meshway ping <target>` | 通过 daemon 发起获准的真实探测，返回实际路径、测量来源及结果；不以 Controller HTTP 耗时代替 Mesh RTT |
| `meshway status` | 读取 daemon 当前事实，区别进程运行、控制连接、配置保存／安装及实际通道状态 |
| 网络切换 | 由 daemon 串行停止旧网络、完成隔离清理，再取得并运行新网络；具体采用 up 参数还是子命令待定 |

listener、承载参数、DNS、access、topology、routing 等业务配置仍在 Controller 管理。CLI 不维护本地 profiles，也不提供另一份业务配置覆盖源。此前确认的获准路由方案选择属于使用选择；具体 CLI 入口另行对齐，不引入整网管理 CLI 或复用 Node 凭据执行管理员 mutation。

接入时设备不收集账户密码、不取得浏览器会话。CLI 可以展示本次浏览器授权入口，但长期密钥和接入结果由 daemon 私有保存。未批准时退出网页不取消设备请求；取消请求仍使用设备持钥证明。`down` 与云端永久删除 Node 的含义不同。

`ping` 的默认目标／服务范围、一次性探测与持续观察的入口尚待定。当前 Console observation API 使用用户会话且要求明确 service；新 CLI 的 Node 凭据请求路径需要补齐正式合同，不能直接冒用 Console 会话或虚构一条业务流获得探测权限。

## 本机 socket 与状态归属

```text
meshway CLI ──本机命令／查询──► meshwayd ──受控调用──► providers
            ◄─结果／状态事件──            ◄─实际观测──
```

socket 是进程间通信通路。状态由 daemon 和组件的唯一 owner 维护，不以 socket 文件或 CLI 缓存充当第二份事实来源。

- Linux 首版建议 Unix domain socket；其他平台使用对应的本机 IPC，精确路径与权限待定。
- IPC 校验本机调用主体。允许操作 daemon 不自动等于 Controller 的网络管理员权限。
- CLI 可以退出或重新连接；其生命周期不承载 Node 身份、网络运行或执行 lease。
- 命令／响应／事件使用共享强类型合同；CLI 不复制 daemon 状态机或远端 HTTP DTO。
- IPC 主要承载控制与观测。高吞吐业务包不逐包经过 CLI 控制 socket。

## 持久化 runner

建议持久保存与动态重建的边界：

| 私有持久保存 | 重启后重新建立 |
| --- | --- |
| Controller 信任绑定、Node 身份及必要待完成接入／换钥信息 | 短期认证会话、运行 instance、执行 lease |
| 保存的完整执行目标、摘要及 saved 回执恢复依据 | 实际安装结果、当前 applied／failed 状态 |
| 当前选中网络、期望上线状态及仍获准的使用选择 | TCP/UDP 通道、打洞尝试、活跃包会话与计数基线 |
| 需要跨崩溃清理的系统资源归属 journal | 在线／可达性证明、探测成功及插件运行状态 |

保存旧目标不允许重启后直接恢复旧授权。再次 up、daemon 重启或旧实例释放后，须按当前控制合同取得新的实例与有效 lease；永久吊销和成员生命周期不能被缓存恢复绕过。

运行目录、IPC 地址等安装参数与云端业务配置分开。私有存储提供原子写入、持久性结果和进程独占；组件只保存自己负责的必要记录，不各建一套完整 Node Config／State 数据库。

## 运行生命周期

推荐流程：

```text
宿主取得私有目录／IPC 所有权
  → 启动时加载兼容插件，建立能力目录
  → 接受 up／恢复期望上线请求
  → 持钥接入，取得 Node 实例与执行目标
  → 校验并私有保存：saved
  → 先建立底层保护，再安装所需组件
  → 如实报告 applied／failed，按获准需求建立连接
```

本机组件有准备和安装顺序，但不恢复 Controller 的全网 two-phase 屏障。saved 只说明目标已保存；applied 说明本机相应目标已安装，仍不等于已建立远端通道或 ping 成功。

撤回、lease 到期、down 和切网必须能独立于挂起的 HTTP 请求触发停止。停止准入／发送后，取消并等待相关任务退出，再释放所拥有的系统资源；TUN 停止后的 Mesh 捕获／拒绝边界仍须保持。不能按整个进程或目的 IP 全局豁免普通业务流量。

正常退出等待各 owner 完成清理；崩溃恢复只按可验证的 journal 处理自己的系统资源，不恢复旧业务会话。未知版本或不明归属的 journal 不作为任意删除宿主规则的依据。
