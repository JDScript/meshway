# Groups 与 Tags

配置草案；类型、默认值和限制供本轮确认。

## Structure

```json
{
  "groups": {
    "group:dev": ["alice@example.com", "bob@example.com"]
  },
  "tagsOwners": {
    "tag:backend": ["group:dev", "alice@example.com"]
  }
}
```

## groups

**类型：** `Record<string, string[]>` · **建议默认：** `{}`

| 部分 | 说明 |
| --- | --- |
| key | 以 `group:` 开头的组名 |
| value | 本网络 User 的邮箱列表；按集合处理 |

建议首版只支持直接用户成员，不允许 group 嵌套。组成员匹配使用 User 身份的节点，不维护第二份“组里的节点列表”；已切换为 Tag 身份的节点不继承该用户的 Group 权限。

未知用户／组引用在保存时报告。邮箱是可读输入，实际引用与历史版本绑定稳定 User ID。用户改邮箱后自动更新受影响配置中的可读引用并记录版本，不改变有效授权主体。

旧邮箱后来被另一个 User 使用时，旧版本回滚仍引用原 User；原主体已失效则报告无效依赖，不把权限转给新占用者。原始 JSONC 和引用绑定均保留历史。

## tagsOwners

**类型：** `Record<string, string[]>` · **建议默认：** `{}`

| 部分 | 说明 |
| --- | --- |
| key | `tag:` 开头的标签名，如 `tag:backend` |
| value | 有权给节点赋予该标签的用户邮箱或 `group:` |

Tag 在这里定义，在 `nodes[id].tags` 中分配。没有独立 Tag ID 或可单独修改的 Tag 数据源。

空 owner 列表只允许网络 Owner／Admin 赋予该标签。非管理员 Tag owner 只能给**本人的 User 身份设备**赋予自己拥有的 Tag；不能修改别人的设备，也不自动获得整网编辑、材料读取或带同 Tag 设备的管理权限。完整矩阵见[操作权限](/v2/permissions)。

保留用户选用的 `tagsOwners` 拼写；Tailscale 的字段是 `tagOwners`，本稿不同时提供两个 alias。

## Selectors

以下是 access、topology 和 routing 可复用的选择器提案；各字段可接受的子集由所属规则定义。

| 值 | 含义 |
| --- | --- |
| `*` | 本网络中的所有节点，不是任意公网目的地址 |
| `alice@example.com` | 使用该用户授权身份的节点，不包含已改用 Tag 身份的节点 |
| `group:dev` | 使用组内用户授权身份的节点 |
| `tag:backend` | 配置中带此 Tag 的节点 |
| `node:<node-id>` | 指定 Node |
| `autogroup:internet` | 公网目的地，仅用于业务目的授权 |

## 有效授权身份

**已确认：节点带 Tag 后改用标签授权身份，不再继承原 User／Group 的 access 权限。** 创建者信息可以保留用于追溯，不因此继续参与用户授权匹配。

| 有效身份 | 可匹配的主体 |
| --- | --- |
| User 身份 | 对应用户及其 groups |
| Tag 身份 | 已分配的 tags；多个标签的允许权限取并集 |

`node:<id>` 和网络内 `*` 仍按节点范围匹配。tagsOwners 只定义赋标签的权限，不让带该标签的节点继承标签 owner 的用户／组权限。

**已确认：原创建用户被移出网络或账户停用时，Tag 身份节点继续存在并按标签策略运行；需要撤销时由管理员单独操作。** 创建者记录不再是此类节点的存续条件，也不提供额外 access 权限。

## 身份切换与生命周期

| 操作 | 结果 |
| --- | --- |
| User 身份节点加 Tag | 切换为 Tag 授权身份，撤退旧的 User／Group 执行许可 |
| 原创建用户离网／停用 | Tag 节点继续按标签策略运行；不自动撤销 |
| 调整 Tag，但仍至少一个 | 重新计算标签权限，不恢复 User 权限 |
| 直接清空最后一个 Tag | 拒绝；必须由设备完成有效用户登录后切换身份 |
| 设备重新登录为有效用户 | 在验证设备与本次登录绑定后切换为 User 身份，清除 Tag 身份并重新发布权限 |
| 管理员撤销节点 | 停止其有效许可，配置回滚不能复活身份 |

同一个 Node 实体可以切换有效授权身份，不按服务器／App 拆节点类型。创建者保留用于追溯，不自动成为恢复身份的依据；主体切换不能继承旧流权限。
