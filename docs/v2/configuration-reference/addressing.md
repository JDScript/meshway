# Addressing · 地址与分配

**V2 设计：网络地址段和 Node 的期望 Mesh 地址统一属于 NetworkConfiguration。** 支持修改地址段、显式指定地址和重新自动分配；修改地址不改变 Node ID、公私钥身份或 User／Tag 身份。具体字段为以下提案，尚未实现新接口。

## Structure

```json
{
  "addressPools": {
    "ipv4": ["100.80.0.0/16"],
    "ipv6": ["fd42:7a65:8800::/48"]
  },
  "nodes": {
    "<node-a>": {
      "hostname": "alice-laptop",
      "identity": { "type": "user", "user": "alice@example.com" },
      "enabled": true,
      "addresses": {
        "ipv4": "100.80.0.10",
        "ipv6": "fd42:7a65:8800::10"
      }
    }
  }
}
```

示例值不是固定默认值。addressPools 定义可分配的地址段，nodes[id].addresses 定义当前期望分配结果；它们和 DNS／授权／路由使用同一配置版本。

## addressPools

| 字段 | 类型 | 缺省 | 含义 |
| --- | --- | --- | --- |
| `ipv4` | `Ipv4Prefix[]` | 新网络由平台补全并保存；编辑省略时沿用 | 可分配的 IPv4 CIDR 集合 |
| `ipv6` | `Ipv6Prefix[]` | 新网络由平台补全并保存；编辑省略时沿用 | 可分配的 IPv6 CIDR 集合 |

- 数组支持增添新池再移除旧池，便于分批改址；不是节点类型或路由方案。
- 显式 `[]` 表示该族没有可分配池；目标配置中的该族节点地址必须全部为 null。
- 同族池必须规范、无重复／重叠；可用范围、保留地址与容量由 Schema／IPAM 校验。
- 不同隔离网络可以使用重叠地址段；执行始终绑定 networkId，一台设备一次只激活一张网络。
- 地址池本身不声明哪些节点拥有地址，也不授予公网／LAN 转发权限。

## nodes[id].addresses

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| `ipv4` | `Ipv4Address \| null` | 节点期望 Mesh IPv4；null 表示不分配该族 |
| `ipv6` | `Ipv6Address \| null` | 节点期望 Mesh IPv6；null 表示不分配该族 |

每节点每族一个期望地址是本稿字段范围；池和地址都可修改。实际切换期间的旧资源另由执行代际管理，不把旧地址作为第二份可编辑分配。

### 省略与显式值

| 输入 | 结果 |
| --- | --- |
| 新 Node 省略 addresses 或其中某族 | Controller 从该族池自动分配并保存实际值；无池则为 null |
| 已有 Node 省略某族地址 | 沿用当前值，不重新随机分配 |
| 显式 IP | 使用该值，必须在目标池内且无重复分配 |
| 显式 null | 清除该族期望地址；旧分配进入退出流程 |
| addresses 为 `{}` | 按成员字段的省略规则处理；不是“清空全部地址” |
| 显式请求重新分配 | 为选定 Node／地址族选择其他可用地址，并保存为完整新版本 |

完整规范化配置始终保存两个成员的确定值。首次自动分配、重分配都由 Controller 完成；Agent 只执行下发，不自行挑地址。无其他可用地址时报容量不足，不把原地址冒充重分配结果。

## 修改地址段

**已确认：普通配置保存发现节点地址不在目标池内时，指出字段并拒绝，不悄悄改掉显式地址。**

Web 提供“重分配受影响节点”的配置操作：

```text
目标 addressPools + 需要重分配的 Node／地址族
  → 保留其余有效分配
  → 为选定项计算可用地址
  → 校验完整目标 Config
  → CAS 同事务提交新池、新地址与执行切换依据
```

该操作仍修改同一份草稿／完整配置，返回新版本和实际分配结果；具体 HTTP 操作编码另定。并发接入或改址使基准过期时重新核对／返回冲突，不能分配同一地址给两个节点。

也可以分步操作：先添加新池 → 重分配一批节点 → 待原池不再有期望分配后移除原池。每次都是正常配置提交，用户能看到哪些节点正在切换。

## 校验与编译

- IP 必须属于目标配置中对应地址族的池；不能用 IPv6 值填 IPv4，不能分配不适用的多播、未指定或平台保留地址。
- 同一网络内唯一。enabled=false 仍保留它在配置中的地址，自动分配不能抢占；需要回收时明确清除分配。
- 自动分配同时排除当前期望地址和未完成退出的旧地址；显式转交一个退出中的地址可作为新目标，但须等待安全激活条件。
- 普通保存的完整目标一次校验，因此可以在同一提交里调整池和多个节点，也能表达地址交换／转交；不是先写 A 再写 B 的逐行更新。
- Node／User／Tag 选择器随新地址重新编译；管理员手写的 IP／CIDR 规则保持原字面含义，不通过全局字符串替换擅自修改。
- MagicDNS 记录从同版 hostname＋addresses 生成；端点公钥、源地址校验、完整路径、出口接收许可与 DNS 下发绑定同一执行发布。
- IPv4／IPv6 采用相同的身份与切换边界；配置能表达 IPv6 不表示当前数据面已实现。Agent 仍校验实际能力、本机路由冲突与资源准备结果。

## 改址与安全切换

配置期望可以一次提交，节点不会同时收到并安装。改址按发布依赖有序切换，允许明确的 preparing／不可用阶段：

相关节点先按[配置应用流程](/v2/configuration-reference/deployment)准备；旧绑定退出是激活的额外前置条件，不能被“全部 prepared”替代。

1. 提交新配置时记录受影响的旧地址绑定，阻止旧配置继续获得新的相关许可／续租。
2. 向持有旧绑定的源、目标及必要中转／出口发布撤回／更新；地址变化的存量流停止，旧 tuple、反向资格和 NAT 不转交给新地址持有者。
3. 先准备新地址所需的系统保护、TUN、DNS 和路由资源，尚未满足激活条件时保持不可执行业务。旧捕获范围在退出期间保留拒绝边界，失败不能落回底层默认路由。
4. 同一 IP 交给另一个 Node 或重新使用前，等待旧绑定所有可能仍有效的执行许可，以及平台管理的回复／NAT／DNS 缓存窗口退出。
5. 激活条件满足后授予相容的新执行许可并切换。Node 如实报告 saved／applied 与问题；配置保存 ACK 不能证明旧流已清除，也不能提前释放地址复用限制。

池缩小／替换时，旧捕获范围按新旧前缀差集和实际资源 owner 回收；不能用清理旧前缀的操作删除仍属于新配置的保护。精确时序和预算由执行合同补齐。

地址变化会中断受影响的 IP 会话；未变地址的无关业务不应仅因源 revision 变化被全网重启。回包仍走会话原路径，不能靠改址把旧会话接到另一目标或绕过必经点。

冷却窗口保护的是平台已知的许可与缓存。任意应用长期缓存裸 IP 所表达的服务意图无法由 L3 地址复用自动识别，不能把冷却期宣传成应用身份保证。

## 持久化与回滚

| 内容 | 权威位置 |
| --- | --- |
| 可分配池 | ConfigurationVersion.configuration.addressPools |
| 当前期望分配 | ConfigurationVersion.configuration.nodes[id].addresses |
| 某次实际执行使用的地址 | 该执行发布中的 NodeConfiguration |
| 当前安装进度 | NodeState.configuration.saved／applied 与资源问题；保留报告来源 |
| 旧地址何时可复用 | 独立的 AddressRetirement 退出依据 |

Network／Node 实体表不再保留可写地址副本。初版可从完整配置构造内存占用索引；若实现 SQL 加速索引，它必须标明源 revision 并随 current 指针原子更新，没有独立写入口。

AddressRetirement 记录旧绑定的退出窗口，不决定当前地址属于谁。Controller 重启／配置回滚不能清掉它；缺少足够的退出依据时保持等待，不能宣布地址已可安全复用。

回滚恢复历史池和期望地址，仍作为新配置提交。校验当前身份、唯一性、有效依赖和退出记录；冲突明确失败，可提交但尚未安全复用的目标显示 preparing。回滚不复活永久吊销凭据，也不恢复旧连接。

注册重试只恢复原 Node 绑定，随后读取当前配置地址；管理员在注册成功后已改址时，旧响应不能把原地址重新写回。
