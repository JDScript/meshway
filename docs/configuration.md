# 地址与配置分发

本切片将控制面持久身份扩展到双栈 mesh 地址、版本化配置、策略预览和 Agent 配置回执。**地址是分配元数据，配置 ACK 是已校验并私有落盘的回执；两者都不表示系统网络已经应用。**

下文是当前多网络、旧版策略与网络内共享 revision 契约。控制面已按网络隔离业务配置和节点快照；平台托管全部承载、用户账户与路由方案仍是后续目标，设备侧只保留登录 / 接入与使用选择。多网络迁移及默认地址池见[网络管理](/network-management)，已确认模型见[产品概念](/concepts)。

::: info 已实现并通过集成验收
双栈地址、配置缓存/ACK与CAS已通过Rust/SDK行为验收；IPv4-mapped IPv6拒绝、文件发布与持久性失败边界保留回归。v3执行与兼容源模式见[执行合同](/p3a-mesh-execution)，检查入口见[开发验收](/development#配置与路由切片)。UI手工验证，不保留浏览器自动化套件。
:::

## 持久双栈地址池

controller 首次建立网络配置时，默认采用 IPv4 `100.96.0.0/16`，并生成一个 ULA IPv6 `/64` 前缀持久保存。每个节点分配稳定的 IPv4 / IPv6 地址，重启保留地址与归属；撤销后保留分配记录，不把地址复用给其他节点。

`serve` 的 `--ipv4-prefix` / `--ipv6-prefix` 用于首次建立地址池时显式指定前缀，包括开发 v1 数据库首次升级。IPv4 必须为规范网络前缀且长度不大于 `/30`；IPv6 必须为 `fd00::/8` 内规范 `/64`。已有网络配置的数据库拒绝不同地址池参数，不会重新编号；日常重启可以省略参数，复用已保存的网络。参数用法可在 controller `serve --help` 查看。

地址分配不创建 TUN、不配置 OS 地址 / 路由，也不建立节点间隧道。节点记录已有[本地 DNS](/dns)发布切片，系统 resolver 接入与地址分配仍是不同操作。

### 当前开发数据库升级

针对此前注册切片产生的 v1 SQLite 数据库，本轮增加事务化、增量升级：

- 在同一升级事务中增加网络配置与节点地址等状态；既有节点（包括已撤销节点）按稳定节点 ID 顺序分配双栈地址。
- 保留管理员身份、节点 ID、节点凭据摘要、注册令牌绑定和撤销记录，不清空数据库重新初始化。
- 地址池容量或升级校验失败时不能留下部分迁移状态。
- 已分配地址的数据库不能通过修改启动参数更换地址池。

这是 Meshway 当前开发数据库从注册基线到配置切片的特定升级范围，并非生产版本长期迁移、混合版本运行或任意旧 schema 的兼容承诺。Agent 的 v1 身份文件继续使用，配置另存 sidecar，不要求重新注册。

升级验收使用 `apps/controller/src/store/tests.rs` 构造的独立 v1 数据库，验证身份保留和容量失败回滚；运行实例是否已升级须以该实例的实际启动结果为准。

v8→v9 进一步将现有配置、身份、地址、策略、回执与运行报告原样迁为第一张网络，不推进原 revision。新网络各自分配地址，同一 IPv4 可存在于隔离网络；启动参数始终校验第一张网络的原地址池，不对其他网络重新编号。

## 全局 revision 与节点回执

本文“全局”指**同一网络内全部业务配置共享**，不同网络的 revision 独立。`revision` 为 `u32`，有效版本从 `1` 开始；`0` 保留给节点的“从未 ACK”。节点清单 `configuration_revision` 和概览中的同名字段表示该网络目标版本，`acknowledged_revision` 表示该节点最后被 controller 接受的回执版本。

| 事件 | revision 语义 |
| --- | --- |
| 新节点注册、节点撤销 | 清单变化，增加全局 revision |
| 管理员修改国家元数据 | 配置输入变化，增加全局 revision |
| 保存变更后的路由策略 | 增加全局 revision |
| 幂等注册恢复、无实际变化的写入 | 不制造新配置版本 |
| 心跳、配置读取、纯预览、ACK | 不增加全局 revision |

`acknowledged_revision = 0` 是从未收到回执；小于当前 revision 表示回执落后；相等只表示 controller 收到当前配置的落盘声明。回执不证明进程仍运行、网络连通或策略已在 OS 生效。

策略保存和国家编辑都以全局 `expected_revision` 做条件写入。即使另一位管理员只注册了节点，也可能使旧草稿保存返回 `409`。Web 保留冲突草稿；编辑基准 revision 仅在成功保存或管理员显式重新读取后更新，预览看到较新 revision 不会自动推进保存基准。

## 公共配置与稳定摘要

节点以自身 bearer 读取 `GET /api/v1/agents/configuration`。controller 从凭据决定身份和网络，不接受调用方任选节点 / 网络 ID；回复 `ConfigurationSnapshot { digest, payload }`，公共 peers 和策略仅来自同一网络。

`payload` 为 `NodeConfiguration`，包含：

- `schema_version: 1` 和全局 `revision`。
- `network`：IPv4 / IPv6 地址池。
- `node`：本节点公共资料；`peers`：其他有效节点公共资料。
- `routing_policy`：可分发的有效策略。
- `policy_valid` 和 `diagnostics`：保存的策略是否仍有效及其诊断。

公共 `MeshNode` 只含 `id`、`name`、必填可空 `country`、`mesh_ipv4`、`mesh_ipv6`。管理视图使用更完整的 `NodeSummary`，包含版本、注册 / 联系 / 撤销时间和回执进度。配置快照不带凭据、临时联系时间或 ACK 状态，避免心跳和 ACK 改变配置摘要。

摘要为整个 `payload` 的 SHA-256，**包括 revision**；编码为小写十六进制。规范 JSON 使用紧凑 UTF-8，递归按字典序排列对象键，保留数组顺序；规则和必经节点不能为了排序而重排。相同节点、相同 revision 应得到稳定 payload / digest；不同节点的自身绑定不同，不能互换摘要。

摘要用于一致性检查，不是独立数字签名；节点身份仍由控制面 bearer 建立，远程传输保护仍依赖部署层 TLS。

## 校验、私有落盘、再 ACK

Agent 同步顺序为：

```text
确认私有身份文件与父目录持久性
  → 节点 bearer 拉取自身配置
  → 校验 schema、节点 / controller 绑定、digest、网络清单和策略
  → 检查本地版本单调性
  → 私有、原子地发布配置 sidecar
  → 确认私有文件与父目录 fsync 成功
  → ACK 当前节点的 revision + digest
```

身份文件仍使用 `--state` 指定路径，配置 sidecar 为 `<state>.config.json`；默认示例是 `.meshway/agent.json.config.json`。它沿用私有目录 / 文件和原子写入要求，身份凭据不会被复制进公共配置。

Agent 接受有效新版本，或相同 revision / 相同摘要的重试。损坏响应、未知 schema、绑定错误、摘要不符、非法网络 / 策略、更旧版本及同版本不同摘要在发布前被拒绝，保留既有缓存且不 ACK。发现本地缓存损坏时报告错误，不用新身份或静默覆盖恢复。文件写入失败则必须按下述提交阶段处理。

### 文件发布与持久性是两个阶段

共享写入实现 `crates/protocol/src/local/write.rs` 在发布前打开父目录，写入并同步私有临时文件，再原子发布，最后同步已打开的父目录。原子发布是提交点，不能把所有写入错误都描述为“旧文件仍保留”。

| 结果 | 文件与 Agent 内存 | 后续行为 |
| --- | --- | --- |
| `NotCommitted` | 尚未发布，目标未被此次写入替换，原文件保留 | 返回失败，不 ACK |
| `CommittedNotDurable` | 已发布的新文件可见，但崩溃后持久性未确认；Agent 内存保留已发布值及版本下限 | 返回失败，不 ACK，不能只把内存回滚为旧值 |
| 发布及同步均成功 | 私有文件和目录项的持久性已确认 | 才可继续发送 ACK |

例如父目录为 `0300`、允许创建但不可读时，预先打开目录会在发布前失败；真实的发布后目录同步失败则属于 `CommittedNotDurable`。CLI 文件错误结束当前调用，后续重试可以恢复。

**每一次 ACK 都重新要求私有缓存文件和父目录 fsync 成功**，包括摘要未变而省略重写、以及进程重启后加载已有缓存的情况。省略重写可保持缓存 mtime 不变，不能省略持久性确认。节点凭据文件也在使用前重新确认持久性。恢复成功前不会发送 ACK，也不能把本地可见文件视为持久成功的证明。

仅测试构建启用的故障注入覆盖发布后的目录同步失败、相同缓存重试、重启与恢复；实际 `0300` 权限失败另有行为测试。证据见[文件失败验收](/development#新切片验收清单)。

保存的源策略因撤销而失效时，controller 分发可校验的 deny-all 有效策略并带诊断；Agent 可以保存这一安全快照。`policy_valid: false` 描述源策略需要修复，不意味着允许安装损坏规则。

ACK 发送到 `POST /api/v1/agents/configuration/ack`，请求只含 `revision` 和 `digest`：

| 情况 | controller 结果 |
| --- | --- |
| 当前节点、当前 revision、完全一致的摘要 | 接受并记录该节点回执 |
| 旧版本、未来版本或错误摘要 | `409`，不记录为当前版本已确认 |
| 已撤销节点拉取或 ACK | `403` |
| 凭据缺失或无效 | `401` |

若落盘后、ACK 前全局版本已变化，controller 返回 `409`；缓存保存成功不等于回执成功，Agent 需要再拉取当前版本。网络请求失败也不能把回执伪装成成功。

Agent CLI 提供 `sync --state …`；`run` 每轮先心跳再同步，`status` 展示本地 `stored_revision`、`stored_digest` 和双栈地址。`status` 不查询服务端 ACK，也不确认崩溃持久性；无缓存时版本为 `0`。同步收到匹配的 ACK 响应后才输出成功回执；ACK 竞争返回 `409` 时，每次同步最多尝试三轮，再交给 `run` 的退避逻辑。文件错误结束调用，由后续调用在恢复后重试。Web 回执标签为“已校验保存”，不表示网络已应用或在线。

## 策略失效与国家元数据

管理员可以读策略、预览草稿、条件保存，以及条件编辑节点 `country`。来源国家从清单派生；互联网目的国家仅作为显式预览提示，当前没有自动 GeoIP。

撤销有效节点后，该节点从公共配置清单移除，但持久身份与地址分配记录保留。若撤销使策略引用非法，保留策略源文档供管理员修复，分发空规则 + 默认 reject 的整体拒绝策略及诊断。原本的默认 direct 不得成为坏引用的回退路径。具体匹配语义见[分类与有序路径](/routing)。

## 容量边界

当前源码设置策略最多 128 条规则、每条 8 个 `via`、每条合计 32 个来源 / 目标 selector、策略 JSON 128 KiB；配置序列化上限 1 MiB、持久节点数量上限 1024（包括保留地址的已撤销节点）。配置管理请求另有 HTTP body 限制，完整错误契约以生成 OpenAPI 为准。

这些限制用于约束单实例控制面的编译和快照大小，不代表性能容量基准。边界及容量失败事务行为的测试见[验收记录](/development#新切片验收清单)；容量失败不能部分提交或删除已有节点。
