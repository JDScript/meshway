# 邻接、建连方向与协议插件

**已确认的实现方向：**建连方向与业务方向独立；中间节点验证直接发送者与转发权限；协议通过可扩展接口接入；先在 Linux 环境验证。本文区分这些产品约束与仍需实现验证的机制。

## 三种不同的方向

```text
策略路径：NYC ──→ LAX ──→ SHA
建立连接：NYC ──→ LAX ←── SHA
邻接通道：NYC ←─→ LAX ←─→ SHA
```

SHA 可以主动连接 LAX 上的 VLESS / Trojan server。两端完成 Meshway 认证后，LAX 使用同一条已接受的通道把业务帧发给 SHA；不要求 SHA 暴露公网 listener。

VLESS / Trojan 的建连角色与目标请求有方向性，已建立的 TCP stream 则为全双工。这里运行的是 Meshway 帧协议，不是让普通代理服务端凭空创建任意反向代理连接。两个方向的业务权限仍分别检查。

WireGuard 的对等模型也不保证公网可达；NAT、防火墙、endpoint 发现和穿透需要独立处理。

## 节点声明

| 概念 | 含义 | 不代表 |
| --- | --- | --- |
| Capabilities | 实现了哪些协议、dial / accept 与收发能力 | 已经启用 listener |
| Listeners | 本机开启的接收入口与协议配置 | 自动具备公网入口 |
| Endpoint candidates | 同网段地址、域名、映射等可能可达的入口 | 实际连通或身份可信 |
| Connect policy | 应主动连接谁、使用哪些候选及维持方式 | 可以任意跳过策略节点 |
| Services | 可提供的密文中继、互联网出口或子网路由职责 | 已获得控制面授权 |
| Established channels | 当前经过认证的真实邻接及承载状态 | 两个方向的业务都被允许 |

节点声明须与管理员授权、运行时探测区分。Tailscale 的路由服务广告与 endpoint / DERP 信息也承担不同职责，不能用一个“advertise”字段替代上述边界。

## 已接受连接也是可用下一跳

转发器请求的是“到节点 SHA 的、满足指定承载及安全要求的邻接通道”，而非无条件执行 `dial(SHA.address)`。

连接管理器可复用 dial 或 accept 得到的通道。候选不可用时按已配置的同邻接主备策略处理；失败不改变逻辑路径，也不放宽加密与身份要求。

没有公网入口的节点可维持少量常驻连接。后续的控制面协调、按需反向拨号、UDP 打洞与基础设施中继是独立能力；控制面参与协调不意味着控制面默认转发业务数据。

### 现有代理服务器

```text
SHA Agent 的 VLESS 客户端
  → LAX 上的普通 VLESS server
  → LAX 的专用 Meshway 接收端
```

代理连接目标固定到专用接收端时，LAX Agent 可以通过该 socket 的返回方向向 SHA 发送帧。标准代理仅需正常转发字节，两端 Meshway 继续认证身份。该代理本身不因转发了一条连接而自动成为可被授权和追踪的 Meshway 节点。

## 安全与性能边界

### 建路与逐包处理

建连时验证节点密钥并绑定邻接，建路时检查路径及转发权限。逐包路径使用已经认证的会话和授权状态，进行消息认证、重放检查、查表与有界批量发送。

业务负载在源与最终 Mesh 终点之间加密，中间节点无需解析业务 IP 或域名。逐跳安全通道可能仍有自己的加解密成本。代理 UUID / password 只负责代理接入，不能替代 Meshway 公钥身份。

中继验证直接发送者及允许的转发上下文，不宣称独立证明每一个包都由原始源生成。最终解密端需要验证业务来源、目标与授权；可见的 `source_node_id` 或路由标签本身不是身份证明。

### 插件边界

首选编译期 registry 与独立协议 crate。稳定前的小模块不必全部拆成 crate，也不承诺动态 Rust ABI。

协议边界分别表达 stream / datagram、实际最大消息尺寸、可靠性与有序性、buffer 所有权、批量提交、背压、错误和连接生命周期。VLESS 的 UDP 代理若运行在有序 stream 上，必须保留这种实际传输语义。

```text
原始承载 → 已认证邻接 → 获授权路径 → 批量业务帧
```

`dial` 与 `accept` 最终产生同一种可用邻接抽象。协议插件连接成功不等于绕过核心身份与授权检查。

## TUN、userspace networking 与 ICMP

完整 IP 模式将包通过 Meshway 隧道交给对端 TUN / 路由；流代理模式可以在接入或出口处使用 userspace TCP/IP stack，将流转换为代理连接。密文中继无需运行完整 TCP/IP stack。

普通 VLESS TCP/UDP 出口没有通用 ICMP 转发语义；完整 IP 包经 Meshway 封装后可以作为 VLESS 负载，ICMP 由 Meshway 端点处理。实际支持范围取决于端点实现、MTU 和 ICMP 返回处理，不从“采用 VLESS”自动推导。

ICMP 可通过与原生 traceroute 可显示所有中继是两个目标。真实 `meshway trace` 仍需要受认证的数据面观测；规划路径不是观测结果。

## 实验顺序

1. 独立测试身份与显式路径授权，验证真实双向通道和反向建连。
2. 用原生 datagram 与 VLESS stream 检验共同接口的能力差异。
3. 在隔离 Docker 网络中比较裸 iperf3、相同拓扑的内核转发和实际 Meshway 路径。
4. 用实验结果推进生产公钥绑定、controller 配置分发及 Web 状态；配置 ACK 与数据面应用继续分开。

实验配置与密钥独立于现有注册身份。静态实验 allowlist 不等于生产 ACL / 撤销传播方案；这些范围须随验收证据明确记录。
