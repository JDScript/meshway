# 产品概览与概念

Meshway 以 **Tailscale 为常规产品基线**，提供身份驱动的私网互访，并扩展可插拔的自定义 transport 与按域名 / IP 经有序指定路径的路由。Mesh 私网互访和互联网分流同为首版目标。本文描述**已确认目标**；实现差距见下方表格，决策原文见[产品对齐记录](/product-alignment)。

## 网络、用户与设备

- 一个 controller 管理多张隔离网络。成员、地址、DNS、授权、路由和配置均属于所选网络；隔离须落实到服务端与数据面。
- 一台设备同一时间只接入一张网络，可保存多个接入并切换。
- 首版账户由 controller 本地管理：邮箱 + 密码，密码仅存安全哈希。仅通过管理员 / 网络 Owner 的邀请注册并加入指定网络，现有管理员迁移为第一个 Owner；邀请与重置链接手动转交，首版不发邮件。OIDC 后续接入。
- 设备归属登录用户；服务器类设备可用预分配 tag 的接入密钥。Agent 使用浏览器链接登录，App 使用系统浏览器 SSO；登录凭据、节点身份和管理权限分开。
- Agent 与 App 使用统一节点模型。路径中的任务决定中转职责，实际能力与可达性决定能否承担任务；不按设备类别预设中继资格。

## 四层策略

连接、授权与 Mesh 内路由是一张网络的一套配置，对所有设备相同，**与规则顺序无关**。出口路由是唯一采用有序规则的层。

| 层 | 回答的问题 | 已确认语义 |
| --- | --- | --- |
| 连接 | 哪些节点可直接建立承载？ | 默认允许可达节点直连；allow 取并集，node / tag block 始终优先。删除默认允许即为手动连接图。有 listener 可被拨入，无 listener 只主动拨出；业务方向独立于建连方向。 |
| 授权（Access） | 谁能访问什么？ | grants 叠加，只允许、未匹配即拒绝、规则取并集。新网络默认模板为成员全部允许。 |
| Mesh 内路由 | Mesh 流量必须经过谁？ | 可选有序必经节点；无规则自动选路，node > tag > `*` 越具体越优先，同级冲突保存时报错。 |
| 出口路由 | Mesh 外流量从哪里出去？ | 按路由方案组织：公共规则 + 当前方案规则 + 兜底；规则有序 first-match。 |

连接按已授权流量需要建立，不预先全连。直连受阻或不可达时，可经允许的连接自动中转并保持 E2E；自动化不能改变授权或绕过必经节点。设备所在位置影响可达性，不另维护一套 Mesh 配置。

## 路由方案

生效顺序为 **公共规则 → 当前方案的有序规则 → 方案兜底**。公共规则由管理员定义，所有方案都生效且始终在前；兜底为出口 / `direct` / 不接管。

- 匹配域名后缀（DNS 标签边界）、IP 段或规则集；目标为候选出口（优先级主备）或 `direct`，可指定出口前中转。
- 内置 **仅 Mesh**（只有公共规则）、**全局经 X**（每个允许出口自动生成）与 **自动**。自动按 STUN 观测的设备公网 IP 所属国家 / 地区选择方案，不使用控制面连接来源 IP；无法判断时使用其兜底方案。
- 用户在 App / CLI 从管理员允许的方案中切换，管理员可按用户 / 设备锁定。这是使用选择，不是设备配置；切换会中断经旧出口的存量连接。
- 出口或网段使用仍须 grants 允许；含未授权目标的方案分配时保存报错。
- 管理员在 Web 显式开启节点“可作为出口”，Agent 按下发完成转发 / NAT。出口覆盖所有离开 Mesh 的流量，包括互联网和出口所在局域网，不单设 subnet router。
- 规则集由 controller 下载、更新、管理并编译下发，设备不下载数据集。首版只支持域名后缀与 IP 段，不能精确转换的条目须报告；编译生成等价不重叠前缀表，并提示被前序规则完全遮蔽的规则。

## 平台托管与使用流程

管理员在 Web 创建网络与邀请 / 接入密钥 → 用户浏览器登录并接入设备 → 平台生成和下发 listener、承载、DNS、出口及策略 → 按授权需求自动建连 → 用户按允许范围选择路由方案。

添加节点时保留可选 listener 配置，后续可在 Web 修改；默认承载参数与凭据由平台生成，Web 可覆盖允许协议、优先级及逐段约束。VLESS / Shadowsocks 等服务于 Meshway 内部承载，终端通过 Meshway App 接入。

设备侧仅保留接入 / 登录及路由方案选择。手工 profiles、DNS / STUN 启动参数、逐对拨号均是需要收敛的现状，不是目标日常流程。
