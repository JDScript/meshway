# 分类、授权与有序路径

**用户已确认：** 支持域名 exact / prefix / suffix 与 CIDR 分类，结合来源位置和节点身份，指定有序中间节点及独立出口。以下规则形状用于解释语义，尚不是可提交的 API 或配置格式。

## 先描述流，再决定动作

分类至少需要以下概念输入：

| 输入 | 用途 | 注意事项 |
| --- | --- | --- |
| 来源节点身份 | 选择来源策略、执行授权 | 未来由认证机制建立，不信任自报名称 |
| 来源位置标签 | 例如“美国来源” | 标明是观测结果还是管理员属性 |
| 域名及上下文来源 | exact / prefix / suffix | 来自受控 DNS、FakeIP 或代理等；允许未知 |
| 目标 IPv4 / IPv6 | CIDR 分类、实际连接 | 域名关联可能不唯一 |
| 流信息 | 协议、端口及流绑定 | 是否全部进入首版规则待定 |

### 匹配建议

- **Exact**：规范化后的完整域名相等。建议忽略 DNS 大小写、处理结尾点并统一 IDNA 表示。
- **Suffix**：按标签边界匹配。建议 `example.com` 同时匹配自身和 `a.example.com`，不匹配 `badexample.com`；是否包含根域应在最终契约明确。
- **Prefix**：已确认需要此能力，但“完整域名的文本前缀”还是“标签级前缀”尚待决定。不要把它默认为 keyword、wildcard 或 regex。
- **CIDR**：对实际目标地址执行 IPv4 / IPv6 网段判断，不将地理域名集合自动改写为 IP 集合。

建议采用**有序 first-match**：第一条完整匹配的规则决定路由动作。多字段的 AND / OR、无匹配行为及最终默认动作仍需在协议冻结前确认。

## `via` 是有序路径，`exit` 是终点职责

示例意图：美国节点访问中国相关域名，经 LAX 中转，由 SHA 出口访问互联网。

```yaml
# 语义草图：当前程序不读取此配置。
match:
  source_country: US
  destination_domain_set: china-domains
route:
  via: [lax]
  exit: sha
```

当来源为 NYC 时，逻辑路径是：

```text
NYC ──→ LAX ──→ SHA ──→ 外部目标
         via     exit
```

- `via` 中的节点按顺序经过；`[lax, tokyo]` 不是任选一个的候选集合。
- `exit` 明确外部流量在哪个 mesh 节点终止隧道并出网。
- 访问 mesh 内 SHA 时，SHA 是目的节点，不需要把它混称为互联网出口。
- 源节点在路径中出现、重复 hop、路径循环或能力不足，需要编译期与运行期检查。

初始建议是把“有序中间节点 + mesh 目标 / 外部出口”分别建模；最终路径对象、路径长度限制与默认出口尚未冻结。

## 路由匹配不能替代授权

规则选中了 `NYC → LAX → SHA`，仍要独立验证来源身份能否访问目的资源、使用 LAX 转发和从 SHA 出网。允许使用一个路由并不自动授权它可到达的全部目标。

建议由控制面编译分发授权范围，Agent 在相关边界执行；具体凭据与每跳验证协议尚待设计。拒绝与无匹配应有可区分的诊断原因。

## 必经节点失败时

**禁止为了可达性静默绕过必经节点。** LAX 不可用时，不能偷偷改成 NYC 直连 SHA。

两个不同层次的故障处理必须分开：

1. **传输切换**：仍连接 NYC 和 LAX，尝试该邻接的其他健康候选。详见[多传输](/transports)。
2. **路径切换**：选择另一条被明确授权的逻辑路径。必须满足原策略的必经约束，或由显式政策变更允许新路径。

所有候选用尽时，建议使受影响流失败并报告哪一段不可达。自动路径重算、预配置备选路径及其批准语义尚待决定。

## 流绑定、回程与策略变更

建议首版为每条流绑定逻辑路径、出口与传输选择，避免包级路径变化导致乱序和状态错配。外部出口承担返回流量映射，回程优先沿同一逻辑路径返回；**这些都是建议默认，不是冻结协议**。

后续需要明确：

- NAT / conntrack 的归属、超时和 IPv6 行为。
- 策略更新对既有流和新流分别何时生效。
- 身份撤销或授权收回是否立即终止既有流。
- 出口改变导致源地址变化时的连接失败语义。
- 非对称回程是否受支持，以及如何做授权与诊断。

这部分必须通过真实三节点转发测试确定，不能只用策略对象单元测试证明“多跳可用”。
