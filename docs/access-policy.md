# 端点访问授权与 JSONC

**Access 决定谁能访问谁，Routing 决定怎么走。** 两者使用独立的策略源，控制面联合编译后，才向沿途 Agent 分发精确有序路径授权。

## 默认动作与顺序

Access 的默认动作可选 `allow` / `reject`，新建策略为 `reject`。规则自上而下 first-match；第一条命中规则决定允许或拒绝，未命中才采用默认动作。

默认 `allow` 只覆盖当前 controller 网络中已注册、未撤销的节点，包括之后注册的节点。它不等于允许互联网出口，也不覆盖其他网络或未注册身份。尚未发布公钥的节点可以成为 ACL 主体，但数据面在具备有效绑定公钥之前不为它安装业务路径。

| 选择器 | 含义 |
| --- | --- |
| `*` | 当前网络中的活动注册节点，必须单独出现在该选择器列表中 |
| `node:<完整节点 ID>` | 一个具体节点，界面显示名称与 Mesh IP |
| `tag:prod` | 管理员分配了 `tag:prod` 的活动节点 |

每侧列表内部为 OR，可混合 node 与 tag。来源和目标之间为 AND。每侧最多 32 项，策略最多 128 条规则。

`bidirectional: true` 在该规则的同一个位置检查反向来源 / 目标，不会生成一条偷偷移动到别处的规则。更靠前的 reject 仍然有效。这是明确的双向许可，**不是状态型回包跟踪**；单向规则的回程需要另一条规则或默认允许。

## 标签属于管理员配置

在 `/tags` 维护标签目录和节点成员；Agent 无权通过自报标签取得访问权限。编辑描述、增加标签不会清空原节点分配。仍被节点分配或策略引用的标签不能删除；撤销节点会清理其成员关系，但保留策略原文供检查。

空标签组合法。未知标签或明确引用的未知 / 已撤销节点会使源策略无效，生效授权整体为空，不会跳过坏规则而落入 default-allow。

## 图形化与 JSONC 是同一份草稿

`/access` 的规则卡片和 `/routing` 的图形编辑器均可切到 JSONC：

```jsonc
{
  // 其余节点对默认拒绝
  "default_action": "reject",
  "rules": [
    {
      "id": "prod-to-web",
      "source": ["tag:prod"],
      "destination": ["tag:web"],
      "action": "allow",
      "bidirectional": true,
    },
  ],
}
```

标签须先在目录中创建，再分配给节点。编辑器从 Rust OpenAPI 导出的 schema 提供字段、枚举、节点和标签补全；错误定位到行列和字段路径。JSONC 支持注释和尾随逗号，拒绝重复对象键。

- 图形修改保留未修改位置的注释。
- 无效文本保留原样，图形编辑暂停；显式修复或放弃后再继续。
- 站内导航保留未保存文本和原 CAS 基准。
- 保存同时提交结构化 `policy` 与 `source_jsonc`；服务端验证两者完全一致，原样保存注释。
- 只改注释也属于源文档变更，推进全局 revision；并发保存不能静默覆盖另一份文本。
- Routing 的管理员源文档可保留原始写法，Agent 接收的有效路由配置仍由 Rust 编译器规范化。

## 联合 Flow 预览

访问页与拓扑页从 controller 的已保存策略读取统一结果，依次展示：

1. Access 命中的规则、方向或默认动作。
2. Routing 命中的规则与有序路径。
3. 各段近期认证邻接报告。
4. 数据面执行条件及尚缺的前提。

预览不是 trace，也不证明应用已经收到包。`execution_supported` 只描述当前实现和配置前提，真实 ICMP / HTTP 仍需实测。邻接观测独立检查 revision、新鲜度、节点身份和实际候选关系。

## 升级与内部边界

SQLite v5→v6 保留节点 ID、凭据、公钥、地址和路由源。原有完整路径授权按端点合并，互为反向的条目折叠为一条双向规则，默认仍为 reject；原始 v5 授权另表保留。路径约束转由 Routing 表达，这是本轮确认的语义变化。

Agent 的 schema-version-1 `NodeDataplane.access_policy` 仍为内部 `{ grants: [{ id, path }] }`，不直接接收管理员的 selector 规则。控制面根据 Access、Routing、标签和公钥编译精确路径，Agent 再验证该路径；`allow` 不跳过必经节点，也不降低 E2E。

当前运行层每节点最多 64 个联合 peer 身份和 128 条内部路径。通配符展开超限会被拒绝，不截断许可；编译复用已准备的路由上下文，并跳过尚无公钥的运行时端点。

验收包含真实 controller / Agent / Web 的标签创建、节点分配、单卡双向规则、匿名保存拒绝、JSONC 注释持久保存、跨视图 / 导航保留无效文本、并发 CAS 冲突和撤销成员清理。隔离 Docker 的真实 ICMP / HTTP 检查见[托管数据面](/managed-dataplane#隔离的三节点验收)。
