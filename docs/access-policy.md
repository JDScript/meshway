# 访问授权（Access）

**Access 决定谁能访问什么，路由决定怎么走。** 两者独立求值，控制面联合编译可执行的精确路径授权；允许访问不能跳过必经节点，也不能降低 E2E。

## 已确认目标：叠加 grants

- 只写允许规则，未匹配即拒绝；规则取并集，与顺序无关。更具体规则不会覆盖宽规则的允许。
- 新网络默认模板为成员全部允许；删除 / 收窄模板后按明确 grants 授权。
- 当前网络内使用 `*`、管理员分配的 tag、node，后续加入用户 / 组。每条可显式双向；双向许可不等于状态型回包。
- 出口和外部目的地也须授权，目的地可为“互联网”、具体 IP 段或域名后缀。路由方案分配不能包含未授权目标。

上述是已确认模型，完整四层策略见[产品概念](/concepts#四层策略)。

## 当前实现与迁移

当前 `MeshAccessPolicy` 仍是默认 allow/reject、first-match 的端点规则；selector 支持 node/tag/`*` 和显式双向，控制面根据 Access、Routing、标签和公钥编译内部 `{ grants: [{ id, path }] }`。这些内部精确路径 grants **不等于目标管理员 grants 模型已上线**。

旧语义仅作为迁移输入保留：默认允许且零规则应等价转为全部允许 grant；已有 allow/reject 必须无损转换，无法等价表达的部分报告给管理员，不能静默放宽。此前 SQLite v5→v6 的完整路径到端点授权迁移保留身份、地址与旧授权记录，不代表本次 grants 迁移已经完成。

当前未知 / 已撤销的明确节点引用或未知 tag 使源策略失效，生效授权整体为空，保留原文供修复。通配符和标签按活动成员展开；尚无绑定公钥的端点不安装业务路径。每节点联合 peer 上限 64、内部路径上限 128，超限拒绝而非截断许可。精确字段与容量以[生成协议](/protocol)为准。

## 标签与草稿

当前标签由管理员在 `/tags` 维护，Agent 自报不能获取权限；仍被节点或策略引用的标签不能删除。标签是当前节点属性，用户身份 / tag identity 的后续迁移不可直接从现有字段推断。

`/access` 与 `/routing` 均已有图形化 / schema JSONC 编辑器：

- 两种视图共享同一草稿与 CAS 基准，切换不能覆盖无效文本、注释或未保存编辑。
- schema 从 Rust OpenAPI 生成；支持注释、尾逗号，拒绝重复对象键。
- 保存同时校验结构化 `policy` 与 `source_jsonc` 一致；只改注释也属于源文档变更。
- `409` 保留草稿，只有保存成功或显式重新读取才更新基准；预览不推进 CAS。

这里不列旧版 JSON 示例；编辑时使用当前生成 schema，避免把迁移字段当作目标模型。

## Flow 预览与验证

统一 Flow 预览分别展示端点许可、规划路径、近期认证邻接以及数据面执行条件。`execution_supported` 表示实现 / 配置前提，预览不发真实 trace，也不证明应用收到包。

已验证的旧版行为包括标签分配、单条双向规则、JSONC 注释与无效草稿保留、匿名 action 拒绝、CAS 冲突和撤销。真实 ICMP / HTTP、必经节点故障、lease 与撤回证据见[托管数据面](/managed-dataplane#隔离的三节点验收)；状态型回包仍需独立实现与验收。
