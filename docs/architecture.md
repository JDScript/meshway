# 架构与设计状态

Meshway 的目标是一个以节点身份为基础的 Rust mesh 网络：根据来源身份、位置与目标域名 / 地址选择路径，用显式的有序节点连接跨区域网络，并为每条逻辑相邻连接提供多种传输候选。

## 控制面与数据面

```text
                         ┌────────────────────┐
                         │ Next.js 管理界面    │
                         └─────────┬──────────┘
                              生成 TS SDK
                                   │
                         ┌─────────▼──────────┐
                         │ Rust controller    │
                         │ 凭据 / 持久清单     │ ← 已实现
                         │ IPAM / 策略 / 配置  │ ← 已实现并验证
                         └─────────┬──────────┘
                              生成 Rust 客户端
                                   │
       ┌───────────────────────────▼───────────────────────────┐
       │ Agent：身份 / 心跳 → 校验配置 → 私有缓存 → ACK         │ ← 已实现并验证
       │ 之后：本地 DNS → 分类 → 授权 → 路径 → 传输候选         │ ← 数据面目标
       └───────────────────────────┬───────────────────────────┘
                                   │
                         NYC → LAX → SHA → 目标
```

已验证的 HTTP 基线通过注册建立节点凭据身份，再用心跳维护联系记录。本轮增加地址与配置意图的分发和回执，仍不建立 TUN、DNS、mesh 公钥认证或数据转发。HTTP schema、逻辑预览和配置 ACK 都不是网络连通性的证明。

控制面的设计职责是维护身份、节点清单、授权与策略版本，编译和分发一致的配置。Agent 执行本地解析、分类、转发、连接管理与诊断。业务流量经过指定 Agent，controller 不应被默认当作业务中继。

### 身份与观测信息分开

控制面凭据身份由管理员授权注册、服务端分配节点 ID 和节点 bearer 建立。心跳由凭据派生身份，调用方不能任选节点 ID。节点名、IP、国家或城市标签都不能单独证明身份；mesh 对等节点的公钥认证与 E2E 握手仍需后续设计。

本轮国家字段是管理员维护的部署元数据，来源国家与 mesh 目标国家从清单派生；互联网目标国家只接受显式预览提示，不自动 GeoIP 定位。国家标签与“这个身份被授权访问某资源”是不同判断，后续如增加观测来源也须明确来源和更新方式。

### 当前持久化与部署选择

controller 的单实例 SQLite 记录节点、注册令牌消费和撤销状态，数据目录锁阻止同时启动第二个实例。Agent 的私有状态文件在网络 I/O 前保存节点凭据，支持重启和响应丢失后的身份恢复。当前文件存储使用 Unix `0700` 目录与 `0600` 文件。Web 使用 8 小时 HttpOnly / Strict cookie，仅在服务端携带管理员凭据调用生成 SDK，逐次检查读取与管理 action。`last_seen` 是最近联系记录，`node_count` 包括已撤销节点，不代表健康隧道数。

这一选择不提供高可用或多 controller 复制；远程 HTTPS 由独立部署层终止 TLS。注册恢复、权限与故障语义见[控制面注册与持久化](/enrollment)。

### 本轮地址、策略与配置边界

默认地址池为 `100.96.0.0/16` 和首次生成后持久保存的 ULA IPv6 `/64`。开发 v1 数据库通过事务增量升级，为既有节点按稳定 ID 顺序补齐地址并保留身份、凭据和撤销记录；撤销不回收地址，已有地址池不能通过启动参数重新编号。

注册 / 撤销、国家元数据和策略变化增加全局 `u32` revision，心跳与 ACK 不增加版本。节点拉取自身绑定的公共配置，校验 schema / SHA-256 / 网络 / 策略，私有原子发布并确认文件与目录 fsync 后 ACK 当前 revision 和摘要；相同缓存和重启后也须重新确认持久性。发布后同步失败时新文件已经可见，Agent 保留已发布的内存值但报错、不 ACK。公共清单不携带凭据或联系时间；相同节点、相同 revision 的 payload 与摘要稳定。

策略编译器只处理逻辑意图。保存使用全局 revision CAS；撤销导致引用非法时保留源策略供修复，分发 deny-all 有效策略和诊断。**地址分配不是接口配置，缓存成功不是网络应用，预览路径不是实际 trace。** 详细失败语义见[地址与配置分发](/configuration)。

Web `/routing` 的引导式编辑器显示只读网络前缀、草稿基准 revision、匹配规则、路径及诊断；预览不推进保存基准，成功保存或显式重新读取才更新。国家编辑同样使用 CAS。控制意图切片已验收，mesh 公钥身份、ACL 与真实数据面仍属于后续工作。

## 四个独立层次

1. **分类**：这条流来自谁、去哪里？域名上下文从何而来？
2. **授权**：这个身份是否允许访问目标、使用中间节点和出口？路由匹配不授予访问权。
3. **逻辑路径**：必须依次经过哪些 mesh 节点，最后由谁终止隧道或出网？
4. **传输**：相邻两个节点用哪种承载建立连接？候选必须符合能力与安全模式。

例如 `NYC → LAX → SHA` 是逻辑路径；`NYC ↔ LAX` 可以有多个传输候选。换掉这一段的承载不等于允许跳过 LAX。目标域名、DNS 上游以及控制通道的流量也不能被一个不加区分的 TUN 规则递归捕获。

## 小而清晰的 Rust 边界

初始工作区保持少量模块，待稳定边界出现后再拆分：

| 边界 | 职责 |
| --- | --- |
| `crates/protocol` | Rust 请求 / 响应类型、`routing.rs` / `config.rs` wire 契约、序列化与配置摘要 |
| `crates/policy` | 本轮纯 Rust 策略规范化、引用校验和逻辑预览；无网络 I/O |
| 生成的 Rust control client | Agent 调用 HTTP API，避免手写平行 DTO |
| `apps/controller` | API 路由、凭据权限与 SQLite；本轮 IPAM、revision、策略编译与配置分发 |
| `apps/agent` | 注册、私有身份状态与心跳；本轮配置校验 / 缓存 / ACK；之后的节点数据面 |
| `@meshway/control-client` | 生成 TypeScript 类型、客户端与运行时响应验证 |
| `apps/web` | Next.js + shadcn，消费已交付 API |
| `docs` | 架构、设计状态与验收说明 |

WASM 是未来共享策略编译器的可选方式。仅为 HTTP 客户端共享类型不需要引入 WASM。
