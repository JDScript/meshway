# 观测与延迟

最新观测可以出现在 NodeState；完整测量历史是独立事件存储。它们不能由 heartbeat、query 或 watch 次数推导出来。

## 测量类型

| 类型 | 测量对象 | 不代表什么 |
| --- | --- | --- |
| 邻接 probe | 一条实际认证承载上的往返 | 不是经过多跳的端到端延迟 |
| 路径 probe | 指定完整路径上的端点往返 | 不是各边 RTT 相加，也不是系统 traceroute |
| 建连耗时 | DNS／TCP／TLS／协议／认证等建立过程 | 不是稳定传输 RTT |
| 控制面请求耗时 | Node 与 Controller 的一次请求 | 不是 Mesh 业务连通性 |

## Event fields

事件字段提案：

| 字段 | 含义 |
| --- | --- |
| `measurementId` | 一次真实测量的独立标识，重发不变 |
| `kind` | 测量类型 |
| `source` / `peer` | 有方向的测量端点；source 由凭据绑定 |
| `linkId` / `path` | 本次实际关联；不能确定则明确未知 |
| `configuration` / `instanceId` | 测量所属执行上下文 |
| `startedAt` / `completedAt` | 实际测量时刻 |
| `outcome` | success／timeout／failed |
| `durationUs` | 该次调用完成耗时，缺测／失败为 null |
| `reason` | 类型化失败原因或 null |

是否拆出排队、重试和纯往返耗时，必须以实际可测量边界为准，不能把总耗时重命名成纯网络 RTT。

## 更新规则

- 真实新测量才产生新 ID；相同事件重发幂等，不刷新原时刻。
- 超时不填零；没有发起测量、采样繁忙、队列丢弃和上报失败是不同缺口。
- 对网络／方向／承载／实例／路径分别呈现，不能跨这些变化拼成连续曲线。
- Controller 接受的是有凭据来源约束的自报告，不是独立远端测量证明。
- 建议统一探测来源，健康判断、当前状态和历史订阅同一批真实结果；历史记录者不另发一套探测或直接退休通道。

## 当前实现

现有 30 秒邻接历史和 5 秒健康探测是两条主动入口，底层超时可退休对应通道；历史耗时包含排队和内部重试。listenerless 通道关联、缺口原因和完整路径测量尚需完善。以上统一模型不等于已实现；现有 API／预算见[邻接延迟历史](/latency-history)。
