---
title: 流量路由
description: 用 Mesh 路由指定流量必须依次经过的节点。
---

Mesh 路由在已经获准的业务和连接图上增加路径要求。它不会授予新的访问权限，也不能绕过组网规则中的阻断。

## 指定必经节点

在**配置 → 流量路由 → Mesh 路由**中，设置来源、目标和按顺序排列的**必经**节点。必经节点必须指向具体节点，例如 `node:<节点 ID>`。

例如，开发组访问后端标签节点时必须经过 `core`：选择来源 `group:dev`、目标 `tag:backend`，再把 `core` 的节点选择器加入必经列表。

每个路段从上到下使用第一条匹配规则。没有规则匹配时自动选路。规则顺序因此很重要；前面的宽规则可能让后面的窄规则不再被使用。

## 分段路径仍遵守规则

必经节点把路径分成多个路段，每段还会按其实际起终点查找规则：

```text
A → D 要求经过 C
A → C 又要求经过 B
最终路径：A → B → C → D
```

已经处于路段起点或终点的相应必经边界视为满足。真正需要重复访问节点或相互递归的要求会使路径不可用。

这些分段只改变转发路径。业务来源仍是 A，目标仍是 D，不会因此额外允许访问 B 或 C 上的服务。

## 必经节点不可用时

路径必须保留全部必经节点。某节点停用、无法连接，或某段没有相容承载时，相关路径不可用；系统不会跳过该节点，也不会退到后面的路由规则来绕过要求。

可以在允许范围内使用其他完整路径，但每条都必须满足同样的要求。已建立会话及其回复保留原完整路径。

编辑后，在源节点的**路径**页比较当前配置和草稿的结果。检查通过后应用，再以 `meshway ping` 检查实际路径。详见[路径检查与延迟观察](/docs/console/diagnostics)；请求和返回字段见 [API：评估配置](/docs/api/configuration/evaluate-configuration)。
