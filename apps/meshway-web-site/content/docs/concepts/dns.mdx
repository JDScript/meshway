title: DNS 与 MagicDNS
description: 使用节点名称访问 Mesh 网络中的设备。
---

MagicDNS 把本网络的节点名称解析为 Mesh 地址。名称来自节点的配置主机名，后缀来自网络 DNS 配置。

例如，主机名为 `web`、网络后缀为 `mesh.example` 时，完整名称是 `web.mesh.example`。这里的后缀仅为示例，请使用自己网络中的实际值。

## 使用节点名称

在**配置 → DNS**中查看 MagicDNS 是否开启以及网络后缀。MagicDNS 开启时，网络后缀放在搜索域最前，使系统可以补全短名称。

记录使用当前配置中的 IPv4 和 IPv6 Mesh 地址。节点没有某个地址族时，不会生成对应的 A 或 AAAA 地址记录。更改节点名称或地址后，等待相关配置同步。

## 名称可见不等于在线

名称可见范围按查询节点的访问权限决定：只要允许它访问目标的至少一种业务协议或端口，就可以发现该目标的名称与地址。目标不必在线，也不必已经建立连接。

因此，解析成功不代表目标可达；它也不会额外开放端口。无权访问的名称不会因为 DNS 查询而获得授权。

## Linux 系统 DNS

需要系统名称解析时，daemon 必须成功安装所需 DNS 组件。默认使用 `systemd-resolved` 后端，也可由主机运维显式配置受支持的 `resolv.conf` 代理后端。后端准备失败会报告 DNS 问题，不会把部分安装标成已应用。

`control-only` 模式不安装系统 DNS。普通域名在未启用接管时继续使用系统解析；MagicDNS 的网络名称由 Meshway 处理。

## 排查名称问题

1. 核对 Console 中的主机名、网络后缀和 Mesh 地址。
2. 检查 MagicDNS 已开启，源节点拥有到目标的访问权限。
3. 查看源节点当前配置是否已应用，是否报告 DNS 问题。
4. 用目标的 Mesh IP 执行 `meshway ping`，帮助区分名称问题与路径问题。

`meshway ping` 也接受节点名，但成功不等于某个应用已经通过系统 DNS 完成解析。需要验证应用时，使用它实际访问节点名称。

配置的精确 DNS 字段见 [API：读取配置](/docs/api/configuration/get-configuration)。
