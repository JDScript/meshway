---
title: 节点如何连接
description: 理解监听、拨号、UDP 穿透、中转和端到端保护。
---

节点之间先建立经过认证的连接，再用它承载获准的 Mesh 通信。连接如何建立、使用什么协议，以及允许访问什么服务，是三个不同的问题。

## 监听与拨号

监听器接受连接，拨号器尝试连接对方提供的端点。网络默认拨号器可以被节点继承，节点也可以指定自己的集合或禁止主动拨号。监听需要单独配置。

| 承载       | 建连方式                                                       |
| ---------- | -------------------------------------------------------------- |
| Native UDP | UDP 端点，可使用显式端点或协调穿透                             |
| Native TCP | 一端正常拨号到另一端的 TCP 监听                                |
| VLESS      | 先建立 TCP 连接，再使用配置的 TLS、VLESS 和可选 WebSocket 封装 |
| Trojan     | 先建立 TCP 连接，再使用 TLS 与 Trojan 封装                     |

TCP 类承载也可以由业务接收方先拨入业务发起方。通道建成后可双向承载，但能否发起业务仍由访问权限决定。TCP 业务可以通过 UDP 承载传输，UDP 业务也可以通过 TCP 承载传输。

## UDP 穿透与 STUN

在允许 Native UDP 的连接上，STUN 帮助节点发现其 UDP socket 对外呈现的地址。服务端协调获准的节点交换候选并互发探测，成功后建立认证通道。

这需要服务端配置可用的 STUN 端点。STUN 发现一个地址，不等于该地址一定能被对端访问；防火墙和地址映射行为仍会影响结果。实际成功以建立的通道为准。

## TCP 退路与中转

UDP 穿透失败时，节点只能使用配置已经允许的其他连接或中转路径。需要 TCP 退路时，应同时提供可达的 TCP 监听、相容的拨号器，以及允许该承载的组网规则。系统不会为了连通而启用规则禁止的协议。

中转是在源与目标之间经过其他 Mesh 节点。路径可以自动选择，也可以由[流量路由](/docs/concepts/routes)要求经过指定节点。若要求 A → R → B，就算 A 与 B 能直接连接，也不能绕过 R。

## 端到端保护

Mesh 通信保留原业务端点身份和端到端保护。中转节点转发受保护的通信，目标按原来源和完整路径判断访问许可。已建立会话的回复沿原完整路径返回。

更换某段的承载不意味着可以改变必经路径。控制台的**传输**页和 `meshway ping` 的输出可以帮助区分实际直连、中转、承载与连接获取来源。
