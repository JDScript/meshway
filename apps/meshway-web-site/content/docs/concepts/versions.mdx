---
title: 配置版本
description: 理解草稿、检查、应用，以及节点实际生效的区别。
---

每张网络的配置按版本保存，控制台用 `r42` 这样的标记表示 revision。一次配置提交是一个完整目标；节点分别同步和安装。

## 从草稿到应用

1. **草稿**：你的未提交编辑，保留开始编辑时的配置版本。
2. **检查**：服务端检查目标并返回预览，不保存配置。
3. **对照**：阅读有效修改、前后值、影响节点、警告和永久删除等内容。
4. **应用**：确认后提交；服务端再次检查当前权限和版本，再保存配置。

你的草稿属于当前登录和网络，不是所有管理员共享的编辑区。其他管理员应用配置后，控制台会提示有新版本，并保留你的草稿及原基准。

此时可以从新版本重新开始，或把当前编辑放到新版本上重新检查、重新对照。不会直接覆盖别人的修改。

## 保存与生效

| 你看到的事实          | 它说明什么                     |
| --------------------- | ------------------------------ |
| 服务端已接受配置      | 新的管理目标已保存             |
| 节点已保存（saved）   | 该节点已在本机保存目标         |
| 节点已应用（applied） | 该节点完成该目标所需的本机安装 |
| 实际探测成功          | 对应获准路径完成了往返         |

这几件事可能发生在不同时间。离线节点不会阻止其他节点应用；恢复后会同步当前目标。某个节点失败也不会自动把整张网络退回旧版本。

历史版本曾经应用成功，不表示节点现在仍在线或仍在运行那份配置。

## 历史与恢复

在配置历史中查看版本、比较差异和读取部署进度。恢复历史配置也要检查、对照并确认，且会形成新的版本。

恢复不会撤销永久删除或密钥吊销，也不会恢复旧连接和旧运行状态。旧配置依赖的身份或材料已经失效时，需要处理这些依赖，不能靠恢复重新获得它们。

操作步骤见[编辑配置](/docs/console/configuration)。精确响应见 [API：应用配置](/docs/api/configuration/apply-configuration)与 [API：配置进度](/docs/api/configuration/get-configuration-progress)。
