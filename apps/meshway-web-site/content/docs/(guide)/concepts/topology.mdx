---
title: 组网规则
description: 控制节点之间的直接连接与可用承载。
---

组网规则决定哪些节点之间允许直接连接。规则的两端没有业务方向：A 与 B 的组网关系，和 B 与 A 是同一对关系。

## 规则怎样生效

1. **任意匹配的阻断规则**都会阻断这两个节点的直接连接。
2. 没有阻断时，**第一条匹配的允许规则**决定可使用的承载及其优先顺序；后面的允许规则不合并。
3. 没有任何规则匹配时，使用**未匹配规则时**的默认允许或拒绝。

后面的允许规则不能覆盖阻断。阻断直接连接也不等于禁止经其他获准节点中转；业务访问仍由访问权限决定。

## 允许哪些承载

允许规则可以选择**不限**，或指定 Native UDP、Native TCP、VLESS、Trojan 的有序列表。空列表意味着这两个节点不能直接连接，重复协议会被拒绝。阻断规则始终阻断整条直接连接，承载设置对它不起作用。

“不限”没有边级协议限制，使用平台的承载顺序。指定列表同时表达允许的协议与优先顺序：例如 `"transports": ["vless", "native_tcp"]` 在相同端点来源内优先尝试 VLESS，再尝试 Native TCP。跨承载时，配置端点整体先于本机端点尝试。

每条连接还必须有相容的两端配置：一端启用相应拨号器，另一端提供相应监听，协议参数与运行能力也须相容。只需一个拨号方向可用，建立的通道就可以双向承载已获准的业务。

## 示例：限定为 Native TCP

在**配置 → 组网规则**中添加允许规则，选中两端的节点或标签，将承载设为**指定 → TCP**。检查它是否是首条匹配的允许规则，并确认没有匹配的阻断规则。

随后检查节点的拨号器与监听。允许 TCP 不会替你打开监听端口，也不会让不可达的地址变得可达。

默认允许适合自动选择获准连接，但不会预先连接网络中的每一对节点。要求流量必须经过某台设备时，使用[流量路由](/docs/concepts/routes)。

协议目录与配置字段见 [API：读取传输目录](/docs/api/configuration/get-transport-catalog)和 [API：读取配置](/docs/api/configuration/get-configuration)。
