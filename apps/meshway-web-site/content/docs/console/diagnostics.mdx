---
title: 路径检查与延迟观察
description: 先理解配置如何选路，再观察节点之间的实际往返。
---

Console 提供配置路径检查、历史延迟和实时观察。三者分别回答“按配置应该怎样走”“过去测到了什么”和“现在实际怎样”。

## 检查配置路径

所有者或管理员打开源节点的**路径**页，输入目标节点主机名或 Mesh IP。此页面不填写协议和端口；结果列出匹配的访问授权及其流量范围。

结果包括目标、访问规则、路由决定、候选路径的问题，以及每段连接的组网规则。已有草稿时，可以将当前配置与草稿并排比较，变化的部分会标记出来。

留意结果所属的配置版本，以及结果之后配置或草稿是否又发生变化。路径检查是配置推演，不会证明节点已经建立连接，也不会代替实际探测。

## 发起实时观察

1. 打开源节点的**延迟**页。
2. 从可见节点中选择目标。
3. 选择精确服务：ICMP echo，或带端口的 TCP、UDP。
4. 选择自动路径，或界面提供的已知具体路径。
5. 设置 1–30 秒的周期，开始观察。

管理员可对本网络发起获准观察；普通成员只能以自己的用户身份设备为来源。所选服务仍须有访问权限。例如，TCP 443 的授权不能替代 ICMP echo 的授权。

观察测量的是节点之间获准路径的认证往返，不是浏览器到服务端的 HTTP 延迟，也不证明目标应用端口已经接受连接。

## 怎样读曲线

- **准备中**：等待获准路径准备和建连，不是一次零延迟或丢包样本。
- **有回复**：显示实际往返耗时；路径变化会分段。
- **超时、未发送或未完成窗口**：保留对应标记，不填入 0 毫秒。
- **没有样本**：留空，不推断网络正常或异常。

实时**探测未回应率**按已回复与已超时的探测计算，未发送的探测单列。它不是底层链路的丢包率。

当前观察会在标签页可见时续期。关闭观察面板或离开该节点页签会取消当前订阅；关闭浏览器后订阅随期限结束。同一次登录的其他活动订阅可接管或取消。

## 阅读历史延迟

历史按时间窗口和来源、路径、承载等分组，曲线表示成功探测的平均耗时。没有成功探测的时段没有延迟值，没有记录的时段留空。

历史**未回应率**包含超时或失败的探测，口径与实时观察不同，应按页面的计数阅读。打开历史只读取已有记录，不会启动新测量。

本机也可用 [`meshway ping`](/docs/cli#ping)检查路径。精确操作见 [API：评估配置](/docs/api/configuration/evaluate-configuration)、[创建观察](/docs/api/observations/create-observation)和[查询观察历史](/docs/api/observations/query-observation-history)。
